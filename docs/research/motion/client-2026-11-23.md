# Motion audit: the whole client (2026-11-23)

Audit of `apps/client` at `origin/dev` `ec4ed13cc`, production web build (`bun run --cwd apps/client build`), with the browser-test synthetic hub of `apps/client/browser/synthetic/` inside Playwright (Chromium, headless). Every other host is blocked. No hosted app was opened and no real data was used. Principles: the `apple-fluid-design` skill (motion is a claim; restraint is a finding). Evidence marks: **local** (measured in the browser), **static** (read from code only).

The tasks of this audit are rows MA-1 to MA-7 of [ui-site-language-plan.md](../../plans/ui-site-language-plan.md), Section 3a. No reel was made this time: the fixes are layout and continuity fixes, and the existing reel `motion-reel.html` already shows the vocabulary.

## 3. Baseline (static)

- **Vocabulary.** `apps/client/src/styles/tokens.css`: `--duration-press` 100 ms, `-fast` 150 ms, `-base` 200 ms, `-highlight` 1 500 ms, `-breathe` 2 400 ms; four springs as CSS `linear()` curves (`default` 515 ms, `snappy` 368 ms, `move` 588 ms, `momentum` 405 ms with 1.5 % overshoot); `--stagger-list` 20 ms; loading thresholds 300 and 500 ms. Roles in `$lib/motion/roles/` (`modal`, `popover`, `listRow`, `crossFade`, `drop`, `grow`, `resolve`), shared elements in `$lib/motion/shared/`, view-transition cross-fade in `$lib/motion/view-transition/`.
- **Rules held.** AGENTS.md: motion uses `$lib/motion/` and tokens only. A scan of every `.svelte` and `.css` file outside `tokens.css` found no raw duration and no `transition: all`. Svelte transitions all come from the roles.
- **Reduced motion.** `prefers-reduced-motion: reduce` and the Settings Motion row (`data-motion`) set press, stagger and all springs to 0 ms. `duration-fast` and `duration-base` stay, so opacity fades of 150 to 200 ms remain (measured: the same five 200 ms fades on `/devices` in both modes). Scale is 1 in every frame. This is the specified form (MOT-040, MOT-041); MA-7 asks if it stays.
- **Traversal.** A route change is a 200 ms fade of the page (`page` layer). No view transition runs on a route change (0 `startViewTransition` calls in every load and navigation). Shared elements are JS copies that travel between `[data-shared]` keys.

## 5. Opportunities

### MA-1 Shared name from List and phone rows

- **Where.** `lib/devices/card/DeviceTable.svelte` (the name link, line 90) and `lib/devices/phone/PhoneRows.svelte` (line 52). `DeviceCard.svelte` line 62 and `DetailBar.svelte` line 51 already use `sharedItem('device-name:<id>')`.
- **Today.** The List view is the default. A click on a row fades the whole page out and the device page in (200 ms); the name is seen twice, in two places, with nothing between.
- **Proposal.** Attach `sharedItem(\`device-name:${device.id}\`)` to the name in a table row and a phone row, as the card does. The name travels from the row to the title with `spring-move`; Back travels it home.
- **Communicates.** "This page is that row."
- **Reduced motion.** `sharedItem` reads the preference: no travel, the page fade only.
- **Cost, risk, verify.** S. Risk: two `[data-shared]` keys of one device in one page (List and Grid never show together). Verify: per-frame rect of the copy from the row to the title, and Back.

### MA-2 Settings holds its place

- **Where.** `routes/settings/+page.svelte` line 96 (`LinkDevicesSection` with `onVisibility`), the Notifications section skeleton.
- **Today.** At 240 ms Notifications is at y 304 with a skeleton of 852 px. At about 700 ms "Devices on the link" mounts above it (162 px) and Notifications grows to 1 524 px. The sections under it move down about 1 250 px. CLS 0.31 (1280) and 0.53 (390), also under reduced motion.
- **Proposal.** Settings shows its sections when all the sections it waits for know if they show, or each late section takes its place under the sections that are already there; the Notifications skeleton takes the geometry of its loaded rows (MOT-007). No new animation: the fix is that nothing moves.
- **Communicates.** Nothing should; a page that moves under the reader says "do not trust where things are".
- **Reduced motion.** Same; the fix removes the jump for everyone.
- **Cost, risk, verify.** M. Verify: CLS under 0.01 at 390 and 1280 with a 400 ms API delay, in both modes, in a 1 600 px window too.

### MA-3 Phone tally reserves its line

- **Where.** `lib/devices/phone/PhoneHead.svelte` (the `tally` group above `phone-search`).
- **Today.** The tally mounts after the devices come; search and the list move 44 px down (CLS 0.026).
- **Proposal.** Keep the tally's line from the first frame (an empty line of the same height while the devices load), then fade the counts in place (`crossFade`).
- **Cost.** S. Verify: CLS 0.000 at 390.

### MA-4 Phone device page detail

- **Where.** The device page `detail` block at 390 px.
- **Today.** It grows from 310 to 511 px and moves 6 px when data comes (CLS 0.009).
- **Proposal.** The skeleton takes the height of the loaded block. Cost S.

### MA-5 Hosting overview (owner: Hosting)

A block of the Hosting overview moves 20 px (1280) and 39 px (390) when its data comes. The Hosting screens belong to the serveros-hosting-ui session now; this audit builds nothing there.

### MA-6 Code padding spring (owner: Threads)

`lib/code/shell/ChatHeader.svelte` line 76 and `lib/code/chat/ChatColumn.svelte` lines 61 and 67 animate `padding-inline-*` with `spring-default`: layout on every frame. A `translate` of the content, or a width change without animation, gives the same result without layout. Not measured; Code belongs to the Threads session now.

## 6. Vocabulary proposals

None. The tokens and roles cover every proposal above. MA-7 (OD-MOT-1) asks only whether the reduced form changes.

## 7. Do not animate

- The tab panel of a device page: it swaps on one frame, and that is right.
- Route changes stay a 200 ms fade; a sliding page would claim a direction that the navigation does not have.
- Readings (usage, uptime) cross-fade; they never count up.
- Focus rings, the live log line and the Settings Motion row itself.

## 8. Unknowns

- Search on `/devices`: the fill did not change the row count inside the 700 ms window that was sampled, so the filter motion was not observed.
- `/projects` and `/builds` redirect to `/devices` in these fixtures; not audited.
- Chromium only; WebKit not run this time. Headless frame rates are not device frame rates.
- The desktop and mobile shells were not run; only the web build.
