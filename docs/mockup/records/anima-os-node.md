# The record of the mockup anima-os-node

- Mockup: [anima-os-node/index.html](../anima-os-node/index.html)
- Owner: [spare-computer-os.md](../../proposals/spare-computer-os.md) Section 17, product redesign and decision consolidation
- Screens: None yet. Proposed refinement of the installed console and selected Calamares installation states.
- State: Proposed
- Compared: Not compared with a redesigned implementation. Source baseline is recorded in the owner plan; this is a new design study, not a replacement for the existing built-console reference.
- Differences: Interactive synthetic data only; no live actions. Five console destinations and running, waiting, capacity, disconnected, failed, empty and locked states. Installer refinement shows Review, Installing, Complete and Failed. Code handoff is illustrative; the node cannot approve coding actions. Dark/light token roles derive from Graphite, spacing and typography from design/tokens, and embedded Plex fonts from the client. Appearance selector is a design-review control, not proposed product UI.

- Visual refinement: existing Carbon processor, RAM, disk and SSH/RDP/VNC shapes are embedded from the client; compact controls have accessible names and hover/focus tooltips. Navigation retains icons with labels. The hero reuses the anima-site particle geometry bundled at 0373144, with a brief entrance and static settled rendering; reduced motion skips the entrance. Subtle frost glow is limited to branding and capacity. Destructive actions and operational status retain visible text.

- Overview uses a simple home outline instead of the dashboard/chart glyph, following operator feedback that the latter implies analytics. This mockup-specific outline is pending addition to the shared icon inventory if approved.

- Capability audit: owner Section 17.19 maps existing console actions to the redesign. Restored screen-off (including locked state), distinct restart/shutdown, enrollment/account and self-host flows, network, disks, display/rotation/motion, updates/rollback and recovery review panels. Added representative battery, uptime and stale-reading states. Panels and confirmations are illustrative; full error-state and functional parity remain outstanding.

- Operator disposition: exploratory only; operator is not happy with the mockups as a complete design. Combine selected ideas with a faithful port of the existing console. Lock hero/full-width layout and finite particle transition are demonstrated; production motion qualification and full continuity remain outstanding. Terminal includes a sample Graphite/frost Powerline-style prompt.

- Final council limitations: ordinary settings dialogs are illustrative; locked sample resets the previous connection scenario; changing reduced motion does not finish an already-running Web Animation. These are not approved production behaviors. Section 17.21 records staged readiness and the required corrections in implementation. Installer completion illustrates the existing offline preview flow; stable pre-install pairing remains governed by Section 16.4/F3.
