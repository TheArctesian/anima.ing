## Cause

Read in the code of `dev` at `f69fc0170` and seen in a run of the child by hand.

- The child fetch process (`crates/daemon/src/model/fetch/child.rs`, `work`) made the deadline of the download with `tokio::time::timeout` before it called `block_on` of its runtime. A tokio timer that is made outside a runtime has no reactor: the child panics with "there is no reactor running" before it sends a request.
- The daemon reads no reply word from a child that panics, so each `runtime_install` gives `failed` with the cause `source_failed`, on each computer and for each source.
- The tests did not find it: they call `finish` and `download` from a test runtime, not the child program.

## Correction

On the branch `fix/model-fetch-runtime`:

- [x] The child makes the timer in the runtime: `within` runs the work and its deadline in one `block_on`.
- [x] Tests in `child.rs`: work on a thread with no runtime ends with its value; work past its deadline gives nothing. With the timer made before `block_on`, both tests fail with "no reactor running".
- [ ] Step 1 of HT-120 again with a build of `dev` that holds the correction.
