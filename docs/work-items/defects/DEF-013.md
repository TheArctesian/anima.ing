## Cause

Read in the code of `dev` at `60887ac1e` and seen in step 4 of HT-119.

- Section 9 of the contract says that the cgroup of each server is below the cgroup of the daemon, "which its unit delegates", and that a start with no delegation fails with `containment_failed` (`no_delegation`).
- `make` in `crates/daemon/src/model/tree/linux.rs` took a cgroup that it could make (`create_dir` below its own cgroup) as proof of delegation. Under the systemd user manager each unit cgroup belongs to the user, delegated or not, so the folder is always made.
- Without delegation systemd owns the cgroup tree of the unit: it can move a process out of the server cgroup or remove that cgroup, and the containment of Section 9 no longer holds.
- systemd 255 on `pop-os` sets no extended attribute on a delegated cgroup, so the cgroup itself does not say whether it is delegated.

## Correction

On the branch `fix/model-delegation-check`:

- [x] `make` first asks systemd (`crates/daemon/src/model/tree/delegation.rs`): it finds the unit that holds the cgroup of the daemon in `/proc/self/cgroup` (the last part that is a service or a scope; `--user` when it is below `user@<uid>.service`), runs `/usr/bin/systemctl [--user] show --property=Delegate --value -- <unit>`, and accepts only the answer `yes`. Each other answer, a `systemctl` that fails or does not answer within 5 s, and a cgroup that no unit holds give `containment_failed` with `no_delegation`. The answer is asked once for each process.
- [x] Unit tests of the unit that holds a cgroup and of the answer.
- [x] The server tests in `crates/daemon/tests/it/model_work/` skip unless they run in a unit with `Delegate=yes`, as step 1 of HT-119 says (`systemd-run --user --scope -p Delegate=yes`).
- [ ] Step 4 of HT-119 again with a build of `dev` that holds the correction.
